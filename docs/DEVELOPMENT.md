# MuseWork Plus 改造与验收

## 基线

上游 [15453b3](https://github.com/baijiu666/magpie-MuseWork/tree/15453b33138609d8fc41e9fcaa40e70764ed938a) 的 73 项测试通过。其 `toolcall` 关闭，请求只转换 `messages.content`，回复只转发正文和推理。用真实 DeepSeek V4.1 Flash 会话发送 `tools` 加指定函数的 `tool_choice`，上游仍按普通文本回复并到达 `session.idle`，没有产生该客户端函数的调用事件。现有抓取中的 `component_type: "tool_call"` 是 MuseWork 内部执行的工具。

原版在 12 路同账号冷启动时分别请求 12 次智能体、模型目录、积分余额和套餐。取消时同一会话删了两次。慢读暂停后，上游会继续读到结束。浏览器断开 DevTools 后，原版已发出的命令仍悬挂。

## 实施方案

- 统一解析 MuseWork SSE 为增量和结束事件。流式按下游读取推进，非流式直接聚合，同一份正文和推理只经过一次 SSE 解码。会话取消、结束与并发重试共用一套生命周期，每个会话只请求一次删除。删除有独立截止时间，清理期间账号仍占用原有会话额度。
- 客户端工具定义与历史经 MuseWork 的文本内容块传入。每轮使用唯一标记，只在正文识别并校验调用，待上游结束后交给客户端。普通正文按原路径流出，客户端下一轮用调用 ID 回传工具结果。
- 对账号级可缓存数据合并同键并发读取，按新鲜度和容量管理。保留同时最多 256 个近期账号的模型、频道及额度记录，覆盖现有验证负载的 133 个账号。并发队列只有实际工作时占用状态，套餐同时给出任务和会话上限时取较小者。
- 浏览器 DevTools 断开、报错或取消时，让等待中的命令退出并关闭连接。登录截止时间覆盖浏览器探测、令牌请求与等待。

## 验收指标

- Magpie 正常入口完成客户端函数调用、实际执行及结果回传，覆盖 DeepSeek V4.1 Flash 和 GPT-6 Luna。离线验证 SSE 与 JSON、工具选择、并行开关、纯调用、异常和断流。
- 维持原有文本、推理、图片、模型、登录和额度行为。12 路同账号冷启动每种元数据只读一次；跨账号可并行；取消只提交一次删除。
- 在同一重放下慢读暂停不额外排队上游分段。非流式 CPU 与采样堆峰中位至少各降 20%，连续批次强制 GC 后无持续堆增长。通过公开 GitHub 安装并在 Magpie 的 GitHub 插件目录可检索。

## 验收记录

2026 年 11 月 19 日，在 Windows 的独立 Magpie 0.1.1318 和 Bun 1.4.4 下验证。DeepSeek V4.1 Flash 从 SSE 返回指定函数，GPT-6 Luna 从 JSON 自动发出同一函数。客户端实际读取临时文件，使用各自的调用 ID 回传结果，两个模型均返回文件中的随机值。第二轮交换用了相反的响应格式。Node.js 24.18.0 和 Bun 1.4.4 各通过 88 项测试，覆盖文本、图片、工具、取消、队列、元数据和 DevTools 断线。

性能数据来自 Windows 上独立的 Node.js 24.18.0 进程和同一套模拟上游。运行 `node --expose-gc scripts/benchmark.mjs <源码目录>`，分别指向基线和新版。

| 单次取消产生重复删除的会话 | 1 个 | 0 个 |
